# 前端对接说明（页面 → 后端需要补什么）

页面文件：`src/main/resources/static/index.html`（单文件，原生 JS，无构建步骤，25276 字节）。

Spring Boot 会自动把 `classpath:/static/` 映射到 `/`，所以启动后访问 <http://localhost:8080>
就是登录页。**不需要任何额外配置、不需要前端构建、不需要 Nginx。**

但要让它真正能用，后端还差 **3 处**。下面按"必须 / 建议"分开写，每一处都给出为什么。

---

## 一、必须：静态资源要能匿名访问

### 现状问题

`SecurityConfig` 现在是：

```java
.authorizeHttpRequests(a -> a
        .requestMatchers("/api/auth/login").permitAll()
        .requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html").permitAll()
        .anyRequest().authenticated())
```

`/index.html` 落进 `anyRequest().authenticated()`，浏览器打开首页会直接拿到 **401 JSON**
（`{"code":401,"message":"未登录或登录已过期"}`），页面根本加载不出来。

这是个**死锁**：登录页要先能加载，用户才可能拿到 token。

### 改法

```java
.authorizeHttpRequests(a -> a
        .requestMatchers("/api/auth/login").permitAll()
        .requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html").permitAll()
        // 静态资源必须放行：登录页自己要先能加载出来
        .requestMatchers("/", "/index.html", "/favicon.ico", "/assets/**").permitAll()
        .anyRequest().authenticated())
```

⚠️ 注意范围：这只放行"下载 HTML/JS 文件"，页面里调的 `/api/**` 仍然逐个校验 token。
**不要**图省事写成 `requestMatchers("/**").permitAll()`。

### 验收

```bash
curl -i http://localhost:8080/            # 期望 200 + HTML（不是 401）
curl -i http://localhost:8080/index.html  # 期望 200 + HTML
curl -i http://localhost:8080/api/course  # 期望 401（API 仍受保护）
```

## 二、必须：需要一个课程列表接口

### 现状问题

页面的「课程」页要一次渲染 100 门课，但后端只有 `GET /api/course/{courseId}` 单条查询。
前端如果循环 100 次，就是 100 个请求 —— 页面会转圈好几秒，而且压测时等于自己打自己。

### 接口契约

**`GET /api/course`** → 返回全部课程（含库存）

```json
{
  "code": 200,
  "message": "操作成功",
  "data": [
    {
      "courseId": 1,
      "courseName": "课程1",
      "teacher": "教师1",
      "credit": 2.5,
      "startTime": "2026-11-05T16:50:28",
      "endTime": "2027-11-06T16:50:28",
      "capacity": 100,
      "stock": 100,
      "sold": 0,
      "myOrderStatus": null
    }
  ]
}
```

权限：登录即可（`authenticated()`），不要求 `ROLE_STUDENT` —— 管理员也要能看课程列表。

### 实现要点

**`CourseService`** 加一个方法：

```java
List<CourseDetailResponse> listCourses();
```

**`CourseServiceImpl`** 的实现建议**分两次查，不要 JOIN**：

```java
List<Course> courses = courseMapper.selectList(
        new LambdaQueryWrapper<Course>().orderByAsc(Course::getId));
Map<Long, CourseStock> stockMap = courseStockMapper.selectList(null).stream()
        .collect(Collectors.toMap(CourseStock::getCourseId, s -> s, (a, b) -> a));
```

为什么不用 JOIN：库存表的行会被抢课 UPDATE 加锁。JOIN 会把"浏览课程列表"也拖进锁竞争，
抢课高峰时连看课都卡 —— 这和 §3 把库存拆出 `course` 表是同一个道理。

**Controller** 加：

```java
@GetMapping
@Operation(summary = "课程列表", description = "返回全部课程与当前库存，供页面渲染选课列表")
public Result<List<CourseDetailResponse>> list() {
    return Result.success(courseService.listCourses());
}
```

⚠️ **`@GetMapping` 和 `@GetMapping("/{courseId}")` 不会冲突** —— Spring 优先匹配精确路径，
`/api/course` 走列表，`/api/course/1` 走详情。

## 三、必须：`myOrderStatus` 要真的填上

### 现状问题

`CourseDetailResponse` 有 `myOrderStatus` 字段（注释写着"null 表示没选过"），
但 `CourseServiceImpl.getCourseDetail` **从来没给它赋过值**，永远是 null。

页面的按钮逻辑完全依赖这个字段：

| `myOrderStatus` | 按钮显示 |
|---|---|
| `null` | 「立即抢课」 |
| `0` | 「排队中…」（禁用） |
| `1` | 「已选上」（禁用） |
| `2` | 「立即抢课」（可重试） |
| `3` | 「重新选课」 |

字段永远是 null 的后果：**已经选上的课仍显示「立即抢课」，用户点了收到 409「你已选过该课程」** ——
看起来像 bug，其实是前端拿不到状态。

### 实现要点

在 `getCourseDetail` 末尾补：

```java
Long studentId = currentStudentId();
if (studentId != null) {
    SeckillOrder exist = orderMapper.selectOne(new LambdaQueryWrapper<SeckillOrder>()
            .eq(SeckillOrder::getStudentId, studentId)
            .eq(SeckillOrder::getCourseId, courseId));
    res.setMyOrderStatus(exist == null ? null : exist.getStatus());
}
```

列表接口同理，但**不要逐门课去查**（那是 100 次查询的 N+1）。一次查出该学生所有订单做字典：

```java
Map<Long, Integer> statusMap = orderMapper.selectList(
        new LambdaQueryWrapper<SeckillOrder>().eq(SeckillOrder::getStudentId, studentId))
        .stream().collect(Collectors.toMap(SeckillOrder::getCourseId,
                SeckillOrder::getStatus, (a, b) -> a));
```

### 🔴 取 studentId 必须判角色，不能只看 principal 非空

```java
private Long currentStudentId() {
    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    if (auth == null || !(auth.getPrincipal() instanceof Long id)) {
        return null;
    }
    boolean isStudent = auth.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .anyMatch("ROLE_STUDENT"::equals);
    return isStudent ? id : null;
}
```

原因：管理员的 principal 是 `sys_user.id`，而 **`sys_user.id = 1` 恰好等于学生 `S000000001` 的 id**。
不判角色的话，管理员打开课程页会被当成"学生 1 选了什么课"，读到别人的选课数据。
这是"双用户表各自自增主键"这种设计最容易出的错，且不会报任何异常。

## 五、页面的几个设计取舍（不用改，但值得知道）

### 1. 抢课后的轮询

`v3-mq-async` 下 `POST /api/seckill/{id}` 返回 200 只代表**已受理入队**，订单还是 `0 待处理`。
页面因此在抢课后每 400 ms 查一次 `GET /api/course/{id}`，最多 10 次（4 秒），
等 `myOrderStatus` 变成 1 才提示"选课成功"。

这也是为什么第三点（`myOrderStatus` 必须填）是**硬需求** —— 不填的话轮询永远拿到 null，
用户会一直看到"排队中"。

在 `v0` / `v1` / `v2` 策略下订单是同步落库（直接 `status=1`），轮询第一次就返回成功，不影响使用。

### 2. 为什么用 `sessionStorage` 而不是 `localStorage`

关掉标签页 token 就没了，多台机器/多个标签页不会串号。演示项目够用。
真实项目要配 refreshToken，这里没做（见 README「已知局限」）。

### 3. 为什么不用 Vue / React

页面只有一个列表 + 一个订单表，原生 JS 约 200 行就够。
引入构建链（Vite + npm install + 产物目录）会让"克隆下来就能跑"变成"先装 Node 再装依赖"，
对这个项目的目标（验证后端并发）是负收益。

### 4. 颜色语义

- 剩余 ≤ 10 门：进度条转橙色（提醒快没了）
- 剩余 = 0：进度条转红色 + 按钮「名额已满」
- 订单状态：待处理=橙 / 已成功=绿 / 已失败=红 / 已退课=灰

## 六、联调检查清单

后端补完后，按这个顺序验：

```bash
# 1. 静态资源（不用 token）
curl -i http://localhost:8080/ | head -1                 # 200

# 2. 登录拿 token
curl -s -X POST http://localhost:8080/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"account":"S000000001","password":"Abc12345"}'

# 3. 课程列表（带 token）
curl -s http://localhost:8080/api/course -H "Authorization: Bearer <token>"
#    期望 data 是数组，长度 100

# 4. myOrderStatus 有没有填
#    先抢一门课，再查同一门课的详情，myOrderStatus 应为 1
```

浏览器里点一遍：

- [ ] 打开 <http://localhost:8080> 看到登录页（不是 401 JSON）
- [ ] `S000000001` / `Abc12345` 登录 → 看到 100 门课程卡片
- [ ] 点「立即抢课」→ 提示"已提交，正在排队落单…" → 约 1 秒后"选课成功"
- [ ] 卡片按钮变成「已选上」，剩余名额 -1
- [ ] 切到「我的选课」→ 看到那条订单，状态「已成功」
- [ ] 点「退课」→ 状态变「已退课」，回课程页剩余名额 +1
- [ ] 退出 → `admin` / `Demo@2026` 登录 → 课程卡片按钮都是「仅学生可选」，右上角出现「预热全部库存」
- [ ] 刷新页面（F5）→ 仍是登录态（sessionStorage 在标签页内有效）

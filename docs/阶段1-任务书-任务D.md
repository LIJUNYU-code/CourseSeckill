## 2. 先修现有文件的 2 个问题（20 分钟）

### 2.1 🔴 `entity/CourseStock.java` 主键类型写错了

你现在写的是：

```java
@TableId(type = IdType.AUTO)
private Long courseId;
```

**为什么错**：`IdType.AUTO` 的意思是「主键由数据库自增生成」。但 `course_stock.course_id` 在数据库里**不是自增的**（`SHOW CREATE TABLE` 里只有 `PRIMARY KEY (course_id)`，没有 `auto_increment`），它的值就是 `course.id`，是程序手动写进去的。

**后果**：现在只做查询可能碰巧能跑（`selectById` 生成的 SQL 只用到主键元数据），但一旦阶段 2 你要插入库存行（预热门票时 `stock = capacity` 那一步），MyBatis-Plus 会认为主键该由数据库生成，**不会把你赋的 `courseId` 写进 INSERT**，结果要么报错要么插出一条 `course_id=0` 的脏数据。

**改成**：

```java
@TableId(value = "course_id", type = IdType.INPUT)
private Long courseId;
```

`IdType.INPUT` = 「主键由我（程序）自己给」，这是非自增主键的正确声明。`value = "course_id"` 其实可以省略（MyBatis-Plus 默认把驼峰 `courseId` 转成下划线 `course_id`），但显式写出来更不容易在以后被人改错。

### 2.2 ⚠️ `entity/Course.java` 的校验注解要删掉

你现在写的是：

```java
@Max(3)
@Min(1)
private BigDecimal credit;
```

**两个理由都指向「删」**：

1. **位置错了**：`jakarta.validation` 的约束注解是给**请求 DTO** 用的——它回答的是「客户端传来的值合不合法」。实体类回答的是「数据库里这一行长什么样」。两者职责不同。注解挂在实体上，以后任何地方用 `@Valid` 级联校验实体时都会意外触发，而且错误信息会指向一个客户端压根没直接提交的字段。
2. **值也是错的**：`credit` 是 `decimal(3,1)`，能存 0.0~99.9。而你的种子数据里已经有 **3.5 学分**的课了（`课程3`），`@Max(3)` 会直接判定它非法。这条注解现在就是个错的。

**删掉这 3 行 + 对应的 2 个 import。**

### 2.3 ✅ 确认项：Mapper 不需要加 `@Mapper`

你已经写对了——`CourseMapper` / `CourseStockMapper` 都是裸接口，靠启动类上的 `@MapperScan("com.example.seckill.mapper")` 扫描注册。**不用改**。这是更省事的做法（注解和扫描二选一，重复了反而容易在两个地方维护）。

### 3.1 `dto/CourseDetailResponse.java`（补全）

```java
package com.example.seckill.dto;

import io.swagger.v3.oas.annotations.media.Schema;
import lombok.AllArgsConstructor;
import lombok.Builder;
import lombok.Data;
import lombok.NoArgsConstructor;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@Data
@AllArgsConstructor
@NoArgsConstructor
@Builder
@Schema(description = "课程详情（含库存）")
public class CourseDetailResponse {

    @Schema(description = "课程 id", example = "1")
    private Long courseId;

    @Schema(description = "课程名称", example = "课程1")
    private String courseName;

    @Schema(description = "授课教师", example = "教师1")
    private String teacher;

    @Schema(description = "学分", example = "2.5")
    private BigDecimal credit;

    @Schema(description = "选课开始时间")
    private LocalDateTime startTime;

    @Schema(description = "选课结束时间")
    private LocalDateTime endTime;

    @Schema(description = "总名额", example = "100")
    private Integer capacity;

    @Schema(description = "剩余名额", example = "100")
    private Integer stock;

    @Schema(description = "已选人数", example = "0")
    private Integer sold;
}
```

**为什么这些字段、不多不少**：

- `courseId` 单独返回，因为前端拿详情后要发秒杀请求 `/api/seckill/{courseId}`，得有个明确的 id 来源，不该让它去猜。
- `capacity` / `stock` / `sold` 三个都返回，因为它们的关系是 `stock + sold = capacity`（文档 §2 R3 的守恒规则）。前端要显示「剩余 87 / 共 100」，运维要一眼看出数据有没有错。
- **不返回 `version` 和 `updateTime`**：这两个是内部并发控制用的字段，前端不需要，暴露出去等于告诉别人你的实现方案。这是「VO 只装客户端要用的东西」的原则——你在项目一已经踩过实体直接外发的坑（密码哈希泄漏）。

### 3.3 `service/Impl/CourseServiceImpl.java`（补全，这是主要工作量）

```java
package com.example.seckill.service.impl;

import com.example.seckill.common.ResultCode;
import com.example.seckill.dto.CourseDetailResponse;
import com.example.seckill.entity.Course;
import com.example.seckill.entity.CourseStock;
import com.example.seckill.exception.BusinessException;
import com.example.seckill.mapper.CourseMapper;
import com.example.seckill.mapper.CourseStockMapper;
import com.example.seckill.service.CourseService;
import lombok.AllArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

@Service
@AllArgsConstructor
@Slf4j
public class CourseServiceImpl implements CourseService {

   private final CourseMapper courseMapper;
   private final CourseStockMapper courseStockMapper;

   @Override
   public CourseDetailResponse getCourseDetail(Long courseId) {
      // 1. 查课程本体
      Course course = courseMapper.selectById(courseId);
      if (course == null) {
         throw new BusinessException(ResultCode.NOT_FOUND, "课程不存在");
      }

      // 2. 查库存行
      CourseStock stock = courseStockMapper.selectById(courseId);
      if (stock == null) {
         // 数据不一致：课程在，库存行没了。不抛异常（读接口不该因为附属数据缺失就整页 500），
         // 但要留日志让人能发现。—— 这是"防御性读取"的典型写法
         log.warn("课程库存行缺失，按全 0 返回 courseId={}", courseId);
         stock = CourseStock.builder()
                 .courseId(courseId)
                 .capacity(0).stock(0).sold(0)
                 .build();
      }

      // 3. 组装返回
      return CourseDetailResponse.builder()
              .courseId(course.getGetId())      // ← 注意：这里要用 course.getId()
              .courseName(course.getCourseName())
              .teacher(course.getTeacher())
              .credit(course.getCredit())
              .startTime(course.getStartTime())
              .endTime(course.getEndTime())
              .capacity(stock.getCapacity())
              .stock(stock.getStock())
              .sold(stock.getSold())
              .build();
   }
}
```

> ⚠️ 上面故意留了一个错误：`course.getGetId()` 应该是 `course.getId()`。这是提醒你——**不要直接复制粘贴要理解着写**，编译器会拦住它，但我更希望你写的时候就知道。

**三个要点解释：**

1. **为什么查两次库而不是写一个 JOIN？**
   两行 `selectById` 命中两个主键索引，各 ~0.1ms，比一个 JOIN 更简单、更不容易写错。而且这个接口在阶段 4 会被 Redis 缓存掉（v2 版本直接读缓存，一次库都不查），JOIN 的价值就更低了。**先要正确，再要快**——这是 P1 原则。

2. **为什么库存缺失不抛 404 而是返回全 0？**
   区分「客户端的问题」和「我们的数据问题」：
   - `course` 不存在 → 客户端传了个不该传的 id → 404，这是它的错；
   - `course_stock` 不存在 → 是我们造数据或迁移漏了 → 客户端没有错，凭什么给它 404？
   一个详情接口因为附属表少一行就整页打挂（500）是更糟的选择。所以：**记日志暴露问题，接口继续返回可用数据**。

3. **为什么不加 `@Transactional`？**
   方法里只有两条 SELECT，没有任何写操作。事务的意义是「要么全成功要么全回滚」，只读场景没有这个需求，开了反而多一次事务管理器开销和连接占用。**给只读方法加事务是新手最常见的过度设计之一。**

### 3.4 `controller/CourseController.java`（新建）

```java
package com.example.seckill.controller;

import com.example.seckill.common.Result;
import com.example.seckill.dto.CourseDetailResponse;
import com.example.seckill.service.CourseService;
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import lombok.AllArgsConstructor;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@AllArgsConstructor
@RequestMapping("/api/course")
@Tag(name = "课程查询", description = "课程详情与剩余名额")
public class CourseController {

    private final CourseService courseService;

    @GetMapping("/{courseId}")
    @Operation(summary = "查询课程详情", description = "返回课程基本信息与库存；课程不存在返回 404")
    public Result<CourseDetailResponse> getCourseDetail(@PathVariable Long courseId) {
        return Result.success(courseService.getCourseDetail(courseId));
    }
}
```

**注意两点：**

- `@PathVariable Long courseId` 的参数名**必须**与路径里的 `{courseId}` 完全一致。不一致时 Spring 会报「缺少 URI 模板变量」或直接绑不上（除非你写 `@PathVariable("courseId") Long id` 显式指定）。这是路径变量最常见的错误。
- 返回类型是 `Result<CourseDetailResponse>`，不是裸的 DTO。`Result.success(...)` 有泛型重载，直接接上去就行。

## 5. 四个必踩的坑（提前说，省你时间）

### 坑 1：`@TableId(type = IdType.AUTO)` 用在非自增主键上
已在 §2.1 说清。**这是本任务最该先修的一条**，因为它现在不报错、只在阶段 2 插入时爆。

### 坑 2：`service/Impl` 包名是大写
你现在的 `CourseServiceImpl.java` 第一行还是 `package com.example.seckill.service.Impl;`。Java 规范里包名全小写，大写包会带来两个真实麻烦：①某些工具链（IDE 的自动 import、构建脚本的路径匹配）对大小写敏感度不同；②你在项目一已经因为这个吃过一次 `ConflictingBeanDefinitionException`。

**建议就在这次一起改掉**（5 分钟）：

```powershell
# Windows 文件系统不区分大小写，必须两步改名
cd D:\software\seckill-course
git mv src/main/java/com/example/seckill/service/Impl src/main/java/com/example/seckill/service/Impl_tmp
git mv src/main/java/com/example/seckill/service/Impl_tmp src/main/java/com/example/seckill/service/impl
```

然后把两个文件里的 `package com.example.seckill.service.Impl;` 改成 `package com.example.seckill.service.impl;`（用 IDEA 右键包 → Refactor → Rename 更省事，它会自动改所有引用）。

改完**必须** `clean compile`——Maven 增量编译不会删除已消失的 `.class`，`target/classes` 里残留的旧包会和新包抢同一个 bean 名，报 `ConflictingBeanDefinitionException`。这个坑你在项目一踩过，这里别再踩第三次。

### 坑 3：`@PathVariable` 的参数名和路径变量名不一致
`@GetMapping("/{courseId}")` + `@PathVariable Long id` → 启动能过、运行报错或参数为 null。要么参数名写成 `courseId`，要么显式 `@PathVariable("courseId") Long id`。

### 坑 4：import 用错 Jackson
如果你要写 JSON 相关的东西，`ObjectMapper` 必须 import `tools.jackson.databind.ObjectMapper`（Jackson 3），**不是** `com.fasterxml.jackson.databind.ObjectMapper`（Jackson 2，能编译但 Spring 容器里没有这个 Bean）。注解包仍然是 `com.fasterxml.jackson.annotation`（所以实体上的 `@JsonIgnore` 是对的，别去改）。

## 6. 明确不做（本任务范围内）

| 加 Redis 缓存 | 这是 v2 版本的核心内容，现在加了就没有「优化前后对比」的数字了 | 阶段 4 |

### 任务 A：让项目能启动（约 1 小时）

**目标**：双击运行，控制台出现 `Started SeckillApplication in x seconds`。

**要建的文件**

```
src/main/java/com/example/seckill/SeckillApplication.java
```

**要点**
- 启动类必须在 `com.example.seckill` **根包**下。放在子包（比如 `com.example.seckill.app`）会导致
  Controller/Mapper 扫描不到，表现是「接口全 404」或「Mapper 注入失败」，非常难查。
- 加 `@MapperScan("com.example.seckill.mapper")`。你的 Mapper 接口以后在 `mapper` 包，
  不加这句 MyBatis-Plus 找不到它们。（也可以在每个 Mapper 上写 `@Mapper`，二选一，别两边都写。）
- `application.yaml` 里已经排除了 `UserDetailsServiceAutoConfiguration`。为什么：
  Spring Security 默认会生成一个随机密码的 `user` 账号并打印在启动日志里，看着像失败信息，
  而我们用的是自己的 JWT 登录，不需要它。

**自测**

```powershell
cd D:\software\seckill-course
.\mvnw.cmd "-s" "D:\develop\apache-maven-3.9.15\conf\settings.xml" -B -ntp -o "-Daether.syncContext.named.factory=noop" spring-boot:run
```

> 这条命令以后每天都要用，建议存成一个 `run.ps1` 或 IDEA 运行配置。
> `-s` 指定 IDEA 那份 settings.xml 是必须的（本机 Maven 仓库在 `D:\develop\apache-maven-3.9.15\mvn_repo`，
> 默认的 `C:\Users\user\.m2` 几乎是空的）。

**通过标准**：启动日志无 ERROR、无 `APPLICATION FAILED TO START`，进程不退出。

**常见失败**

| 报错 | 原因 |
|---|---|
| `Failed to configure a DataSource` | `application-local.yaml` 里的密码不对，或 MySQL 没启动 |
| `Communications link failure` | MySQL 服务没起（`Get-Service MySQL80`） |
| 启动后立刻退出 | 引了 `spring-boot-starter-web` 之外的东西导致非 Web 应用；检查 pom 没动过 |

### 任务 B：统一响应 + 统一异常（约 1.5 小时）

**目标**：写一个**必然出错**的接口，验证「客户端的错返回 4xx，服务器的错返回 500，且格式统一」。

**要建的文件**

```
src/main/java/com/example/seckill/common/Result.java
src/main/java/com/example/seckill/exception/BusinessException.java
src/main/java/com/example/seckill/exception/GlobalExceptionHandler.java
```

**要点**

1. `Result<T>` 三个字段：`code` / `message` / `data`。静态方法至少两个：
   `success(T data)`、`error(int code, String message)`。加上 `@Schema` 注解（可选，但阶段 5 的
   Swagger 会好看很多）。
2. `BusinessException extends RuntimeException`，带一个 `int code` 字段。
   为什么不用 `HttpStatus` 枚举：业务码和 HTTP 状态码以后可能不完全一一对应（比如 429 限流），
   自己拿 int 更灵活。
3. `GlobalExceptionHandler` 用 `@RestControllerAdvice`。**至少覆盖这 4 种**：

| 异常 | 返回 | 为什么必须处理 |
|---|---|---|
| `BusinessException` | 用它自带的 code | 业务规则失败（库存不足、重复下单） |
| `MethodArgumentNotValidException` | 400 + 第一个字段的错误消息 | `@Valid` 校验失败 |
| `HttpMessageNotReadableException` | 400 + 「请求体格式错误」 | **JSON 写错或字段类型不对**。这条是项目一踩过的坑：漏了它，客户端传 `"gender": "男"` 这种会变成 500 |
| `Exception` | 500 + 「服务器内部错误」 | 兜底。**这里必须 `log.error` 打印完整堆栈**，否则出错了查无可查（项目一第二次踩的坑） |

**自测**（先随便写一个 `GET /api/test/boom`，抛 `new BusinessException(409, "测试冲突")`）

| 请求 | 预期 |
|---|---|
| `GET /api/test/boom` | HTTP 409，body `{"code":409,"message":"测试冲突","data":null}` |
| 故意触发一个 500（比如 1/0） | HTTP 500，**IDEA 控制台有完整堆栈** |

**通过标准**：上面两条都对。自测完把这个测试接口删掉。

### 任务 C：JWT 登录链路（约 3 小时，最重的一块）

**目标**：`POST /api/auth/login` 用 `S000000001` / `Abc12345` 能换到 token，
不带 token 访问受保护接口返回 401。

**要建的文件**（按这个顺序写，每写完一个就编译一次）

```
1. src/main/java/com/example/seckill/entity/SysUser.java
   src/main/java/com/example/seckill/entity/Student.java
   src/main/java/com/example/seckill/mapper/SysUserMapper.java
   src/main/java/com/example/seckill/mapper/StudentMapper.java

2. src/main/java/com/example/seckill/security/JwtUtil.java
   src/main/java/com/example/seckill/security/JwtAuthenticationFilter.java

3. src/main/java/com/example/seckill/config/SecurityConfig.java
   src/main/java/com/example/seckill/config/PasswordConfig.java

4. src/main/java/com/example/seckill/dto/LoginRequestDTO.java
   src/main/java/com/example/seckill/dto/LoginResponseDTO.java
   src/main/java/com/example/seckill/service/AuthService.java
   src/main/java/com/example/seckill/service/impl/AuthServiceImpl.java
   src/main/java/com/example/seckill/controller/AuthController.java
```

**要点（这部分最容易踩坑，逐条看）**

**C-1 实体**
- `@TableName("sys_user")` / `@TableName("student")`
- `@TableId(type = IdType.AUTO)`
- 字段名驼峰 ↔ 列名下划线，MyBatis-Plus 默认开启驼峰映射，不用每个字段写 `@TableField`
- 用 Lombok `@Data`（`@Builder` 可选，方便造对象）

**C-2 JwtUtil —— 两个方法就够**
```
String generateToken(Long userId, String username, String role)
Long   parseToken(String token)      // 解析失败/过期抛异常，由调用方处理
```
- 密钥：`@Value("${jwt.secret}")` 拿到的是 **Base64 字符串**，要 `Decoders.BASE64.decode()` 之后再
  `Keys.hmacShaKeyFor(bytes)`。直接拿字符串 getBytes 会报 `WeakKeyException`。
- claim 里塞 `role`（阶段 7 前端的菜单要按角色显隐）。另外塞 `username` 便于排查。
- 有效期 `@Value("${jwt.expiration}")`，单位毫秒（配置里是 7200000 = 2 小时）。
- jjwt 0.12.x 的 API 和网上 0.9.x 的教程**不一样**：
  `Jwts.builder().subject(...).claim(...).signWith(key).compact()`，
  解析是 `Jwts.parser().verifyWith(key).build().parseSignedClaims(token).getPayload()`。
  搜资料时注意版本，照 0.9 的写得写不出来。

**C-3 JwtAuthenticationFilter —— 三个动作**
1. 从 `Authorization` 头取 token，判断是否以 `Bearer ` 开头（**注意后面有空格**）
2. 解析出 userId + role，构造 `UsernamePasswordAuthenticationToken` 放进 `SecurityContextHolder`
3. **权限字符串必须是 `ROLE_` 前缀 + 大写**：`ROLE_STUDENT` / `ROLE_ADMIN`。
   这是 Spring Security 的 `hasRole("STUDENT")` 会自动补前缀的约定，写成小写或不加前缀，
   后面 `@PreAuthorize` 永远不通过，而且不报错——这是最坑的一类问题。
4. 继承 `OncePerRequestFilter`。**不要注册成普通 servlet filter**，否则一次请求会跑两遍；
   如果发现跑两遍，加一个 `FilterRegistrationBean` 把它的 `enabled` 设成 `false`。

**C-4 SecurityConfig —— 五个必须项**
```java
http.csrf(csrf -> csrf.disable())                    // 前后端分离 + JWT，不用 CSRF token
    .sessionManagement(s -> s.sessionCreationPolicy(STATELESS))   // 不存 session
    .authorizeHttpRequests(a -> a
        .requestMatchers("/api/auth/login").permitAll()
        .requestMatchers("/v3/api-docs/**", "/swagger-ui/**", "/swagger-ui.html").permitAll()
        .anyRequest().authenticated())
    .formLogin(f -> f.disable())                     // 不要登录页
    .httpBasic(b -> b.disable())                     // 不要浏览器弹窗认证
    .exceptionHandling(e -> e
        .authenticationEntryPoint(...)               // 未登录 → 401 JSON
        .accessDeniedHandler(...));                  // 无权限 → 403 JSON
```
- 最后一项（401/403 返回 JSON）很多人不写，结果浏览器收到一个空白页，前端没法判断。
- 加 `@EnableMethodSecurity`，后面阶段 6 要用 `@PreAuthorize`。

**C-5 登录逻辑（AuthServiceImpl）—— 顺序很重要**
1. 先查 `sys_user` 的 `username`（管理员）
2. 查不到再查 `student` 的 `student_no`（学生）
3. **两处都查不到，和「密码错」返回同一句话**：`账号或密码错误`。
   分开提示（「用户不存在」/「密码错误」）等于告诉攻击者哪些账号存在。
4. 密码用 `BCryptPasswordEncoder.matches(明文, 库里的哈希)` 比对，**不要自己 equals**
5. `status != 1` → 403「账号已被禁用」（这个要区分，否则用户不知道为什么进不去）
6. 返回 `id / account / name / role / token`

**自测清单**

| # | 请求 | 预期 |
|---|---|---|
| 1 | `POST /api/auth/login` body `{"account":"S000000001","password":"Abc12345"}` | 200，`data.token` 有值，`data.role` = `STUDENT` |
| 2 | 同上改成 `{"account":"admin","password":"Demo@2026"}` | 200，`role` = `ADMIN` |
| 3 | 密码写成 `wrongpass` | 401「账号或密码错误」 |
| 4 | 账号写成 `notexist` | 401，**提示和上一条一模一样** |
| 5 | `account` 传空 | 400（`@NotBlank` 生效） |
| 6 | 不带 token 访问任意受保护接口 | 401，**返回 JSON 不是空白页** |
| 7 | 带上刚才的 token 再访问 | 不再 401（接口还没写，可能是 404，但**不是 401 就说明认证通了**） |

> 第 7 条是判断「认证链路通没通」的关键技巧：接口还没实现时返回 404 是对的，
> 说明请求已经穿过安全层进到路由匹配了。

## 4. 四个必踩的坑（提前知道能省 3 小时）

| 坑 | 现象 | 原因与解法 |
|---|---|---|
| **Maven 离线报 "present, but unavailable"** | 明明依赖下过了却报缺失 | 必须带 `-s D:\develop\apache-maven-3.9.15\conf\settings.xml`。IDEA 的仓库是 `mvn_repo`，不是默认的 `.m2` |
| **权限字符串大小写** | `@PreAuthorize("hasRole('STUDENT')")` 永远不通过，**且不报错** | 塞进 SecurityContext 的必须是 `ROLE_STUDENT`（全大写 + 前缀） |
| **中文文件写入 BOM** | 编译报 `illegal character: '\ufeff'` | 配置和 Java 文件用编辑器保存（UTF-8 无 BOM），**不要用 PowerShell 的 `Set-Content`**——项目一在这上面栽了 4 次 |
| **Lombok 找不到 getter** | 编译报「找不到符号 getName()」 | JDK 23+ 起 javac 不再自动从 classpath 找注解处理器。pom 里已经配好 `annotationProcessorPaths`，别删 |

## 6. 阶段 2 预告（先别动手）

阶段 2 才是这个项目真正开始的地方：**写一个会超卖的版本，用 k6 打出超卖数据，亲眼看它坏掉。**

那时你会第一次看到：
- 100 个名额卖出 127 个
- `sold` 和 `stock` 加起来不等于 `capacity`
- 数据库 `CHECK` 约束把一个事务打回，日志里出现真实的失败堆栈

**这就是 P1 原则（先复现问题再解决）的全部意义**——不先看到它坏，后面加锁、加缓存都是背下来的知识。
